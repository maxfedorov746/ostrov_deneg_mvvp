Проверка в браузере показала: общая запись с тратой 100 ₽, сбережением 250 ₽ и воздержанием от покупки «Наушники» на 1000 ₽ уменьшила остаток только на 350 ₽, открыла следующую деталь острова и сохранила отчёт по всем трём действиям. После сохранения экран плавно прокрутился к объяснению над четырьмя показателями. Шкалы показали одну следующую цель накоплений и остаток до перерасхода.

## Найдено и исправлено

1. Описание поля `date` в схеме Python перекрывало тип `date` и останавливало загрузку API. Использован отдельный псевдоним типа; тесты повторены.
2. Первый расчёт на поздней дате месяца мог считать дни до создания острова пропусками. Для пользователя без записей деградация теперь равна нулю; добавлена проверка начального состояния.
3. Кнопка принятия дружбы передавала ID пользователя вместо ID запроса. Публичный список теперь возвращает оба идентификатора, экран использует ID запроса.
4. Даты формы вычислялись через UTC и могли смещаться около полуночи. Форма теперь берёт локальную календарную дату.
5. Исходная миграция зависела от текущих ORM-моделей. Заменена явным описанием таблиц и проверена через `alembic check`.
6. Сценарий с суммой остатка мог выглядеть как утверждение о реальном балансе пользователя. Формулировка уточнена как воображаемая ситуация.
7. Пятый уровень было трудно открыть без сценариев, а при нулевой цели добровольное сбережение не давало бонуса. Порог пятого уровня скорректирован до 78; сбережение помогает при любой цели. Оба случая покрыты тестами.
8. Максимальная разрешённая сумма превышала диапазон PostgreSQL `INTEGER`. Денежные поля бюджета и операций переведены на `BIGINT` в модели и миграции.
9. При смене графического стиля анимация зданий переопределила их координаты в SVG. Анимация теперь меняет только прозрачность; положение зданий проверено в браузере.
10. Старые тестовые базы сохраняли числовой тип `INTEGER` после ранней миграции. Добавлена совместимая миграция до `BIGINT`, проверенная на существующей базе с данными и на чистой базе.
11. При новой детализации карты название второго объекта не соответствовало рисунку. SVG изменён так, чтобы «Теплица» действительно выглядела как теплица.
12. После открытия очередного объекта шкала накоплений начиналась с нуля и скрывала уже отложенную сумму. Теперь заполнение отсчитывается от нуля до суммы ближайшей цели; точные пороги проверены до копейки.
13. Для тестировщика без Docker исходный архив раньше требовал отдельного запуска фронтенда и бэкенда. Добавлен готовый локальный web-build и единый скрипт запуска; повторная распаковка и запуск проверены без файлов рабочего окружения разработчика.
14. Браузер запрашивал отсутствующий `/favicon.ico`, что давало две строки `404 Not Found` при запуске. В локальную сборку добавлены значки SVG и ICO, а сервер демо раздаёт оба файла; проверка включена в тест.
15. После запуска новой распакованной копии браузер мог отправить старый токен на `/api/auth/me` и получить ожидаемый `401`. Экран теперь сразу показывает форму входа и объясняет, почему требуется повторный вход.

## Остаточные ограничения и следующие улучшения

- Docker и PostgreSQL отсутствуют в текущей среде, поэтому реальный запуск `docker compose up` и миграция именно на PostgreSQL здесь не проверены. Их следует выполнить на машине команды до демонстрации. Локальный проход использовал SQLite только для проверки API; поставляемая конфигурация Compose использует PostgreSQL.
- Перед публикацией нужны HTTPS, ограничение частоты запросов, защищённое хранение секретов, резервное копирование и проверка процедуры согласия родителя. Чекбокс — только механизм демо.
- Демо-сценарии и отрисовка острова работают без внешних сервисов. Для полностью закрытой первичной сборки следует перенести заранее собранные Docker-образы во внутренний контур.
- Полезные следующие функции: удаление/исправление записи с пересчётом снимка, персонализация сценариев с учётом бюджета, экспорт собственных данных, подтверждаемое родительское согласие, доступность SVG и полноценные тесты браузера на целевых телефонах.

Предупреждение в тестовом выводе касается устаревающего внутреннего типа Starlette TestClient (`anyio.abc.BlockingPortal`); на результат тестов оно не повлияло.
